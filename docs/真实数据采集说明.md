# 新能源公交项目真实数据采集说明

## 当前建议

这个项目最适合先用真实公交班次数据替换文档里的模拟班次数据，再把车辆、电池、充电站、电价和能耗影响因素按公开数据或合理假设补齐。

推荐的第一批真实数据源是香港政府开放数据平台的公共交通 GTFS 数据：

- 数据集：Headway information of public transport services
- 提供方：香港运输署，DATA.GOV.HK
- 更新频率：页面标注为 Biweekly
- 格式：GTFS
- 当前脚本使用的简体中文压缩包：`https://static.data.gov.hk/td/pt-headway-sc/gtfs.zip`

GTFS 能直接提供本项目需要的线路、站点、班次和到离站时刻，适合作为 `trips.csv` 的真实来源。

## 已落地文件

- `scripts/collect_hk_gtfs.py`：下载香港 GTFS 数据，解压并生成项目需要的班次表。
- `data/raw/hk_gtfs/`：原始压缩包和解压后的 GTFS 文件目录。
- `data/processed/trips_hk_gtfs.csv`：规范化后的真实班次样本。

运行方式：

```bash
python3 scripts/collect_hk_gtfs.py
```

默认只取 3 条公交线路和最多 1000 个班次，便于先完成模型与调度实验。如果要扩大规模，可以调整参数：

```bash
python3 scripts/collect_hk_gtfs.py --max-routes 10 --max-trips 5000
```

## 字段映射

| 项目字段 | GTFS 来源 |
|---|---|
| `trip_id` | `trips.txt.trip_id` |
| `route_id` | `trips.txt.route_id` |
| `start_time` | 该 trip 第一站 `stop_times.txt.departure_time` |
| `end_time` | 该 trip 最后一站 `stop_times.txt.arrival_time` |
| `origin` | 第一站 `stops.txt.stop_name` |
| `destination` | 最后一站 `stops.txt.stop_name` |
| `distance_km` | 优先用 `shape_dist_traveled`；没有则用首末站经纬度近似 |
| `candidate_path` | 暂用 `route_id`，后续可接入 OSM 路径或 `shapes.txt` |

## 还需要补的真实数据

| 数据 | 可行来源 | 项目用途 |
|---|---|---|
| 天气温度 | Open-Meteo、香港天文台或目标城市气象开放数据 | 能耗预测特征 `temperature` |
| 坡度/海拔 | OpenStreetMap + DEM/SRTM/OpenTopoData | 能耗预测特征 `avg_slope` |
| 拥堵/速度 | 政府实时交通 API、公交 GPS、地图平台历史速度数据 | `congestion_index`、`avg_speed` |
| 车辆与电池参数 | 车企公开规格、运营报告、论文参数 | `vehicles.csv` |
| 充电站位置与功率 | 运营商公开信息、政府充电设施开放数据、手动采样 | `stations.csv` |
| 分时电价 | 目标城市供电公司公开电价表 | `prices.csv` |
| 真实能耗标签 | 公交运营企业日志最理想；没有时用公开论文参数校准仿真标签 | `energy_samples.csv` |

## 现实建议

公交真实能耗日志通常不公开，所以本科/课程项目里比较稳的做法是：

1. 班次、站点、线路使用真实 GTFS。
2. 天气、电价、地形尽量使用真实公开数据。
3. 车辆参数引用公开车型或论文参数。
4. 单趟能耗标签用“真实路线特征 + 文献校准模型 + 少量噪声”生成，并在报告中明确说明。

这样比纯模拟数据可信很多，也不会卡在拿不到运营企业内部 SOC/能耗日志这一步。
